# isiXhosa Tech Glossary

![Tests](https://github.com/ongeziwecwesi/isixhosa-tech-glossary/actions/workflows/tests.yml/badge.svg)

A REST API and small website for computing and technology terms in English and isiXhosa. You can search in either language, browse by category, and suggest new terms. Suggestions are reviewed before they become part of the glossary.

## Why

isiXhosa is my home language. When I teach programming or explain technology at home, the isiXhosa words for things like *network*, *variable* or *backup* are often hard to find, or people simply switch to English. I wanted one place where these terms live, that anyone can search, and that other developers can build on through an API.

## What it does

- **Search in English or isiXhosa.** Results are ranked: exact matches first, then terms that start with the search text, then terms that contain it. The search ignores capital letters, extra spaces and accents.
- **Browse by category:** computing, programming, internet, networking, data and security.
- **Suggest a term** through the website or the API. A suggestion stays out of the glossary until a reviewer approves it.
- **Review suggestions** through admin endpoints protected by an API key.
- **Interactive API docs** at `/docs`, generated by FastAPI.

## API

| Method | Endpoint | What it does |
| --- | --- | --- |
| GET | `/api/terms?q=&category=&limit=&offset=` | Search and list terms (paginated) |
| GET | `/api/terms/{id}` | One term |
| GET | `/api/categories` | Categories with term counts |
| POST | `/api/suggestions` | Suggest a new term |
| GET | `/api/suggestions?status=pending` | List suggestions *(admin)* |
| POST | `/api/suggestions/{id}/approve` | Approve; adds the term to the glossary *(admin)* |
| POST | `/api/suggestions/{id}/reject` | Reject with an optional note *(admin)* |
| GET | `/health` | Health check |

Admin endpoints need an `X-Admin-Key` header that matches the `ADMIN_API_KEY` environment variable. If the variable isn't set, reviewing is switched off.

Example:

```bash
curl "http://localhost:8000/api/terms?q=network"
```

## Design decisions

- **Separate tables for terms and suggestions.** Unreviewed suggestions never mix with approved terms, so search only ever returns reviewed content.
- **Normalised search columns.** Each term stores a lowercase, accent-free copy of the English and isiXhosa text. Searches run against those copies instead of converting every row at query time. Exact and prefix matches can use an index. "Contains" searches scan the table, which is fine at this size.
- **Escaping LIKE wildcards.** `%` and `_` in a search are treated as normal characters, so a search for `%` doesn't match everything.
- **Duplicate checks.** The same English/isiXhosa pair can't be stored twice, enforced by both the API and a database constraint. One English word can still have more than one isiXhosa term.
- **Plain JavaScript front end.** The website calls three endpoints, so a framework would add more weight than it saves. Text from the database is inserted with `textContent`, never `innerHTML`, so it can't inject scripts.

## Running it locally

You need Python 3.11 or newer.

```bash
git clone https://github.com/ongeziwecwesi/isixhosa-tech-glossary.git
cd isixhosa-tech-glossary
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python scripts/seed.py            # loads data/terms.csv into the database
uvicorn app.main:app --reload
```

Open http://localhost:8000 for the website and http://localhost:8000/docs for the API docs.

To try the review endpoints, set a key before starting the server:

```bash
export ADMIN_API_KEY=some-long-random-string     # Windows PowerShell: $env:ADMIN_API_KEY="..."
```

### With Docker

```bash
docker build -t isixhosa-glossary .
docker run -p 8000:8000 -e ADMIN_API_KEY=some-long-random-string isixhosa-glossary
```

## Tests

```bash
pip install -r requirements-dev.txt
pytest
```

The 31 tests cover search ranking, filtering, pagination, input validation, duplicate handling, the full suggest → review → approve flow, the admin key check and the CSV loader. They run on every push through GitHub Actions.

## Adding terms

Terms live in `data/terms.csv`. Rows without an isiXhosa term are skipped when loading, so the file can hold terms that are still waiting for a translation. The `source` column records where each translation comes from.

## Project structure

```
├── app/
│   ├── main.py          app setup, website route
│   ├── routers/         terms and suggestions endpoints
│   ├── models.py        database tables
│   ├── schemas.py       request and response shapes
│   ├── search.py        normalising text and ranking results
│   ├── auth.py          admin key check
│   └── static/          the website
├── data/terms.csv       the glossary data
├── scripts/seed.py      loads the CSV into the database
└── tests/
```
